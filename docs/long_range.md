## 当前修改

当前为恢复帧率，已默认关闭切片与逐候选统计：`infantry_zoom_enabled: 0`、`infantry_diagnostics: 0`。
下方启用切片的示例仅供后续对比使用，当前运行的是每帧全图推理。

深大模型仍使用现有的640×480输入和已转换的混合精度模型，没有重新训练模型。
相机仍采集标定对应的640×480原图；仅推理前选择窗口并放大，推理后把浮点角点还原到原图。
PnP、相机畸变、相机到机体外参及UART0均按原图坐标工作。

```yaml
# 1启用；0恢复原来逐帧整图推理，用于固定距离A/B对比。
infantry_zoom_enabled: 1
# 每5帧有一帧整图；其它帧轮流搜索或围绕已发现目标搜索。
infantry_full_interval: 5
# 384×288的窗口放大到640×480，线性放大约1.67倍。
# 四个窗口位置是(0,0)、(256,0)、(0,192)、(256,192)，存在重叠。
infantry_crop_width: 384
# 原代码写死4像素。这里降低至3，但不允许重复点、自交或过小面积。
min_corner_edge: 3.0
# 以下继续保留当前设置；不要为了更远而一次全部放低。
confidence: 0.40
pnp_min_confidence: 0.60
min_quad_area: 15.0
```

每个图像帧只有一次模型推理，避免一帧连续跑全图加四个切片的五次开销。
没有目标时按“全图、左上、右上、左下、右下”轮巡；默认静止目标最多约一轮才被对应切片搜索到。
若处理为20fps，一轮约250ms；这只是搜索时序估算，并非实测帧率或识别保证。
发现分数及短边达到要求的目标后，局部窗口随目标移动，仍定期全图巡检。
连续两次跟踪窗口未发现合格目标后恢复轮巡。

显示里的灰框和`ZOOM 384x288`表示本帧推理窗口；`FULL`表示本帧整图。
灰框外的画面仍显示，但该帧不会检测框外的新目标。
当前帧没有可用检测或PnP失败时，仍发送`valid=0`，不把历史检测当成本帧结果。
因此整图帧漏掉远目标时，即使切片帧能够识别，该帧也会无效；有效坐标更新率可能低于图像处理帧率。

## 为什么3米以后可能消失

当前实测内参约`fx=553.47, fy=551.81`，小板角点间距为`135×56mm`。
按正对、忽略畸变的近似关系`像素高度=fy×实际高度/距离`：

| 距离 | 原图约宽×高 |
| --- | --- |
| 3米 | 24.9×10.3像素 |
| 5米 | 14.9×6.2像素 |
| 6米 | 12.5×5.2像素 |
| 10米 | 7.5×3.1像素 |

目标侧转、失焦、灯条过曝或运动模糊都会进一步降低有效特征。
原来写死的4像素短边和模型小目标置信度都可能限制距离，但不能只看代码确定本次失效原因。
尤其在3米处几何门槛通常还不应构成硬限制，应进一步查看模型分数和实拍画面。
切片有机会改善模型对小目标的响应，但插值不能恢复原图缺失的细节，不能据此保证5～10米或定位精度。

## 查看具体被哪一步筛掉

```bash
/usr/bin/python3 -s /home/jhh/code/other_code/vision_fly_detect/tools/infantry_lite.py status
```

只有设置`infantry_diagnostics: 1`并重启后，`PERF`才输出详细候选统计；该统计有CPU开销，默认关闭。
`boxes`、`corners`、`pnp_valid_frames`和推理窗口始终输出。详细字段如下：

- `best_raw_score`：这30帧内模型的最高原始类别概率，尚未经过颜色和角点筛选；它不是特定目标的分数。
- `candidates`：超过检测置信度且符合类别的候选数，尚未做非极大抑制。
- `color_rejects`：颜色不符合或紫色而被过滤的候选数。
- `point_rejects`：角点非有限或越过模型输入边界的候选数。
- `area_rejects`：四角不凸或面积过小的候选数。
- `boxes` / `corners` / `pnp_valid_frames`：30帧累计检测框数、合格四角数、有效定位帧数，三者含义不同。
- `inference_roi`：最后一帧的推理窗口；`last_status`：最后一帧解算状态。

`corner_edge_too_short`表示角点短边不够；`pnp_confidence_too_low`表示检测可显示但分数不足以定位。
完整逐帧状态和坐标保存在板端`target_positions.jsonl`。
